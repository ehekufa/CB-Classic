# Правила переноса и допущения

Таблица покрытия блоков с числами — `docs/BRICKS.md` (генерируется `tools/report.py`).

## 1. Что именно было в архиве

Формат — **Pocket Code / Catrobat**, экспортированный в текстовые файлы:

```
options.txt        {"displayWidth":720,"displayHeight":1500,"orientation":"horizontal",...}
scenes.txt         [["Загрузка",42],["Меню",1],...]
variables.txt      глобальные переменные: [[id,"имя"],...]
arrays.txt         массивы
scene_N/objects.txt      [[имя, id, {"rotation":..,"path":..,"size":..}], ...]
scene_N/functions.txt    [[id,"имя",арность],...]
scene_N/object_M/scripts.txt   плоский поток блоков [имя, аргументы, "on"]
scene_N/object_M/images.txt    [[имя,imageId],...]  + image_<id>.png
scene_N/object_M/sounds.txt    [[имя,soundId],...]  + sound_<id>.mp3
```

Никакого `project.xml` в архиве нет — только этот «плоский» экспорт, поэтому часть
метаданных оригинала потеряна (см. п. 3).

## 2. Как читаются скрипты

`scripts.txt` — это не дерево, а плоская последовательность блоков. Скрипт начинается
с триггера (`start`, `whenTheTruth`, `onTouchObject`, `touchObject`, `startClone`,
`touchBack`) и заканчивается следующим триггером. Вложенность `if/else/endIf`,
`repeat/endRepeat`, `cycleForever/endCycleForever` восстанавливается по открывающим
и закрывающим блокам (`tools/catrobat2lua.py::BrickGen.block`).

## 3. Формулы

Формулы сериализованы **плоским потоком токенов**, который склеивается в выражение:

| в файле | смысл |
|---|---|
| `[["number",3],["number",5],["number",0]]` | `350` (куски числа конкатенируются) |
| `[["number",0],["number","."],["number",5]]` | `0.5` |
| `[["-","-"],["number",2],["number",1]]` | `-21` |
| `[["function","random"],["function","("],["number",0],["function",","],["number",9],["function",")"]]` | `random(0,9)` |
| `[["globalVariable",47],["function","="],["number",2]]` | `var47 = 2` |
| `[["function","touchesObject2",22]]` | сенсор с «зашитым» аргументом |

`tools/catrobat.py` превращает поток в AST (приоритеты операторов, унарный минус,
вызовы функций, скобки), `gen_expr` печатает Lua-выражение с вызовами `E.op_*`.
Поэтому `+` склеивает строки, сравнения числовые при возможности — как в Pocket Code.

## 4. Триггеры: принятая трактовка

| блок | что делаем |
|---|---|
| `start` | запуск при активации сцены |
| `whenTheTruth` | условие проверяется каждый кадр, скрипт стартует **по фронту** |
| `touchObject` | нажатие на объект (press) |
| `onTouchObject` | тап/отпускание (используется как «клик» по кнопке) |
| `startClone` | запуск у клона сразу после `clone` |
| `touchBack` | кнопка «назад» (Esc в окне, `back` в сценарии) |

`touchObject` и `onTouchObject` в моде ведут себя как «нажал» и «кликнул»: в меню
`touchObject` даёт подсветку кнопки (`setBrightness 85`), а `onTouchObject` — переход
в следующую сцену. Это видно по скриптам и воспроизведено буквально.

## 5. Допущения и потерянные данные

1. **Нет начальных координат.** `objects.txt` хранит только `rotation`, `size`, `path`.
   Позиции, которые не задаются блоком `setPosition`, восстановлены по скриншотам
   сцен (`assets/icons/*.png`, их сохранил сам Pocket Code) и записаны в
   `assets/layout.lua`. Это единственное место, где числа не следуют из данных.
2. **Ориентация.** `options.txt` даёт разрешение устройства (720×1500) и
   `orientation: horizontal`; сцена — 1500×720. Проверяется по координатам игры:
   джойстик `(-590,-150)`, атака `(590,-150)`, «назад» `(400,230)`.
3. **Размеры.** `size` объекта — доля (1.0 = 100%), аргумент `setSize` — проценты.
4. **Порядок слоёв без `setLayer`** — порядок объявления в `objects.txt`; клоны
   вставляются сразу над источником.
5. **`function` / `broadcastFun>*`.** В моде это вызовы «функций» (broadcast-сообщений).
   Скриптов-получателей в выгрузке нет, поэтому вызовы логируются как «нет получателей»
   и не меняют состояние. Имена функций сохранены в `assets/project.lua`.
6. **`fbSetValue` / `fbGetValue`.** Firebase заменён локальным key-value хранилищем
   (`saves/db.tsv`), формат ключа `E.fb_key(a,b,c)` = `"a/b/c"` сохранён. Игра работает
   без сети; онлайн-сцены (95/99) видят только локальные записи.
7. **`ask`, `createTextField`.** В оригинале — диалоги Android. В headless-режиме
   ввода нет: `ask` записывает ответ и продолжает, текстовые поля рисуются, но не
   принимают клавиатуру.
8. **Текст.** `showVariable2` и текстовые поля рисуются встроенным шрифтом 5×7
   (латиница); кириллица транслитерируется. В оригинале использовался системный шрифт
   Android, который в архив не попал.

## 6. Заглушки

| блок | почему |
|---|---|
| `createRadialParticle`, `setPositionParticle` | эмиттеры частиц мода; для них нужен свой физический цикл |
| `addBody`, `isSensor`, `setGravityAllObjects`, `setQuareWHHitbox` | физика твёрдых тел (Box2D-подобная) |
| `focusCameraToObject` | камера не реализована: сцена статична |
| звук | MP3-декодера нет: звуки выбираются и логируются |

Все заглушки **не молчат**: пишут строку в журнал (`--verbose`) и инкрементируют
счётчик `E.unsupported`, поэтому «дыры» видно в отчёте прогона.

## 7. Известные расхождения с оригиналом

* Кубики игрока/врага в сцене «Игра» стартуют с координат из `layout.lua`, а не из
  оригинала; из-за этого первая секунда боя может отличаться.
* HP-подписи (`showVariable2`) «прилипают» к объекту только пока скрипт вызывает блок
  в цикле — так же, как в оригинале.
* Ускорение/торможение физики (`addBody dynamic`) не моделируется, поэтому
  отталкивание кубиков и снарядов приблизительное: движение считается по `goSteps`.
* Один JPEG-файлик под именем `.png` (сцена «Кубы», объект «Пашалка») не рисуется.
