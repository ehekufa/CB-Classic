# Происхождение данных

## Задача

Забрать файл из релиза `YOU_DON'T_NEED_IT` и перенести содержимое проекта на C/C++/Lua.

## Проблема с сетью

Ассет релиза — `Cubic_battle_._._._2_8_2026_.zip`, 224 148 815 байт. Прямая загрузка
из этой среды невозможна: GitHub отдаёт ассеты через `release-assets.githubusercontent.com`,
а он заблокирован (весь диапазон 185.199.108.0/22 обрывает TLS — проверено `curl`,
`openssl s_client`, включая попытку без SNI и с подменой `Host`). `gh release download`
падает с `EOF`, API отдаёт `302` на тот же заблокированный хост, `fetch_page` — HTTP 500.

## Решение

Файл скачивает **раннер GitHub Actions** (у него полный доступ в сеть) и складывает
результат в эту же ветку. Забирать результат из песочницы уже можно: `github.com`
доступен.

1. `.github/workflows/asset-probe.yml` — workflow с `gh release download` и `unzip`;
   сначала он собрал **манифест** архива (`ops/manifest.md`): 964 записи, из них
   646 `*.txt`, 122 `*.png`, 15 `*.mp3`, 14 сцен.
2. Затем тот же workflow скопировал в ветку **все файлы < 50 МБ** (`original/`, 826 файлов,
   30 МБ) и сохранил аудит: `ops/sha256-all.txt` (все файлы архива),
   `ops/sha256-imported.txt` (то, что попало в репозиторий), `ops/zip-listing.txt`,
   `ops/excluded-large-files.txt`.

## Что не вошло

* `scene_26/object_21/sound_8.mp3` и `sound_9.mp3` — по 97 495 883 байта, **один и тот же
  файл** (совпадает SHA-256: `14795176a72d1e63f45874cff16b1447f363b3d847a1e866550370d8f95ab788`).
  Это 93% объёма архива; в git не тянем, хеш и размер зафиксированы. При необходимости
  файл докачивается из релиза и кладётся в `assets/scenes/26_igra/021_igrok/sounds/`.

## Проверка целостности

```sh
sha256sum -c ops/sha256-imported.txt      # из каталога original/
```

`ops/sha256-imported.txt` содержит пути вида `./scene_42/icon.png`.
