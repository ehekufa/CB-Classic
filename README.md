# CB-Classic — порт «Cubic battle в новых красках 2.8» на C / C++ / Lua

Исходник — релиз [`YOU_DON'T_NEED_IT`](https://github.com/ehekufa/CB-Classic/releases/tag/YOU_DON'T_NEED_IT)
(архив `Cubic_battle_._._._2_8_2026_.zip`, 214 МБ), внутри — проект **Pocket Code (Catrobat)**:
13 сцен, 123 объекта, 303 скрипта, 153 картинки, 8 звуков.

В репозитории лежит:

| что | где | состояние |
|---|---|---|
| скачанный и распакованный оригинал (все текстовые файлы, скрипты, PNG, MP3) | `original/` | 826 файлов, 30 МБ, без изменений |
| происхождение данных: SHA-256 всех файлов архива, листинг, исключённые крупные файлы | `ops/` | полный аудит |
| картинки и звуки с осмысленными именами + структура проекта для движка | `assets/` | 153 PNG, 8 MP3, `project.lua`, `index.json` |
| конвертер блоков Pocket Code → Lua | `tools/` | покрытие 100% блоков проекта |
| автоматически портированная логика (303 скрипта) | `generated/lua/` | 136 Lua-модулей |
| движок и рантайм | `src/` | C11 + C++17 + Lua 5.4 |
| тесты, сборка, документация | `tests/`, `Makefile`, `CMakeLists.txt`, `docs/` | проходят все проверки |
| Android-проект и сборка APK | `android/`, `.github/workflows/android.yml` | **APK собирается**, [скачать](https://github.com/ehekufa/CB-Classic/releases/tag/apk-latest) |

## Как это устроено

```
архив релиза
   │  (скачивается раннером GitHub Actions: хост release-assets недоступен из песочницы,
   │   см. ops/README.md) 
   ▼
original/  ──tools/catrobat.py──>  разбор формата Catrobat
   │                                 ├── tools/extract_assets.py ──> assets/ + assets/project.lua
   │                                 └── tools/catrobat2lua.py  ──> generated/lua/**
   ▼
src/c/     inflate.c, png.c, io.c        — чистый C: чтение/запись PNG без zlib/libpng
src/cpp/   engine, renderer, lua_api, main — C++: сцены, спрайты, ввод, программный рендер
src/lua/   runtime/engine.lua, runtime/scheduler.lua, boot.lua — Lua: семантика блоков
```

* **C** — декодер/энкодер PNG (свой inflate), файловый ввод-вывод, `stb`-подобный слой без
  внешних зависимостей.
* **C++** — сцены и спрайты, отрисовка (поворот, масштаб, альфа, яркость), попадания,
  клоны, мост в Lua, кадровый цикл, оконный бэкенд SDL2 (опционально).
* **Lua** — вся игровая логика: 303 скрипта сконвертированы в читаемый Lua-код, поверх
  него рантайм блоков и планировщик корутин (параллельные скрипты и `wait` — как в Pocket Code).

## Сборка и запуск

Зависимостей нет: Lua 5.4 вендорен в `third_party/lua-5.4`, PNG/inflate — свои.

```sh
make                 # build/cb-classic
make test            # все проверки (сборка, PNG, конвертер, сцены)

# отрисовать 40 кадров меню в out/menu/*.png
./build/cb-classic --frames 40 --scene 1 --out out/menu

# игра: пропускаем регистрацию профилем и играем джойстиком из сценария
./build/cb-classic --frames 120 --scene 26 \
  --profile "61=Гость,62=123,60=3,3=100,4=6,12=1" \
  --script tests/scripts/joystick.txt --out out/igra
```

### Android

Готовый APK лежит в релизе [`apk-latest`](https://github.com/ehekufa/CB-Classic/releases/tag/apk-latest)
(`cb-classic-debug.apk`, ~32 МБ, arm64-v8a + armeabi-v7a, minSdk 21). Внутри те же
167 PNG, 8 MP3 и 136 Lua-модулей — с собой ничего носить не нужно. Подробности сборки
и структура `android/` — в [docs/BUILD-ANDROID.md](docs/BUILD-ANDROID.md), отчёт
каждой сборки (sha256, содержимое, лог) — в [ops/apk-report.md](ops/apk-report.md).

### Оконный режим (нужен `libsdl2-dev`):

```sh
make SDL2=1
./build/cb-classic --root . --scene 1     # запускается окно, мышь = палец, Esc = «назад»
```

Полезные флаги: `--scene ID`, `--frames N`, `--fps N`, `--size WxH`, `--out DIR`,
`--script FILE` (сценарий ввода: `press x y`, `move x y`, `release`, `back`, `scene ID`),
`--profile "id=значение,..."`, `--check DIR` (проверка синтаксиса Lua), `--verbose`
(журнал, состояние спрайтов и текстовых полей).

## Что уже работает

* полный разбор формата Pocket Code: сцены, объекты, картинки, звуки, переменные, массивы,
  «функции» (broadcast-сообщения), вложенные блоки `if/else/repeat/forever`;
* конвертер формул: плоский поток токенов Pocket Code (`["number",3],["number",5],["number",0]`
  → `350`, `["function","random"],["function","("]…` → `E.random(...)`) разбирается в AST
  и печатается как Lua-выражения с корректной семантикой сравнений и склейки строк;
* движок: позиции/поворот/размер/альфа/яркость/слой, смена картинок по id и по имени,
  `goSteps`, попадания по повёрнутому прямоугольнику, клоны, текстовые поля, смена сцены;
* планировщик на корутинах: `wait`, `waitIfTrue`, `repeat`, `forever`,
  `repeatIsTrue`, условия `whenTheTruth`, события касания/клона/«назад»;
* «Firebase» и `saveVariable` замкнуты на локальное хранилище (`saves/db.tsv`) —
  игра работает без сети;
* программный рендер пишет PNG-кадры (в оконном режиме те же пиксели идут в SDL-текстуру).

## Ограничения (честно)

1. **Начальные координаты объектов в экспорте отсутствуют** — в `objects.txt` есть только
   поворот, размер и путь к картинке. Позиции, которые не задаются скриптом, восстановлены
   по скриншотам сцен и вынесены в `assets/layout.lua`.
2. **Частицы** (`createRadialParticle`, `setPositionParticle`) и физика
   (`addBody`, `isSensor`, `setGravityAllObjects`, `setQuareWHHitbox`) — заглушки:
   записываются в журнал, но не моделируются.
3. **Звук** декодируется и логируется, но не проигрывается: MP3-декодера в проекте нет.
4. **Кириллица в тексте** рисуется через транслитерацию: встроенный шрифт 5×7 —
   только латиница (в оригинале шрифт брался из Android). Графика интерфейса — настоящая, из PNG.
5. **Ввод текста** (`createTextField`, `ask`) в headless-режиме не поддерживается;
   в оконном режиме поля отображаются, но клавиатурный ввод пока не подключён.
6. Один файл в проекте — **JPEG с расширением `.png`**
   (`scene_27/object_47/images/0267_pashalka.png`), он пропускается с записью в журнал.
7. Скрипты-получатели «функций» (broadcast) в выгрузке отсутствуют — вызовы логируются
   как «нет получателей» (особенность модифицированной сборки Pocket Code).
8. Два mp3 по 93 МБ (один и тот же файл) не вошли в репозиторий — см.
   `ops/excluded-large-files.txt` (размер и SHA-256 зафиксированы).

Подробности: `docs/ARCHITECTURE.md` (как устроен порт), `docs/PORTING.md`
(таблица покрытия блоков и все допущения), `docs/PROVENANCE.md` (как данные попали в репозиторий).
