# CB-Classic — порт «Cubic battle в новых красках» (CB In New Colors) на C / C++ / Lua

Исходник — релиз [`No`](https://github.com/ehekufa/CB-Classic/releases/tag/No)
(архив `super.kortohka.zip`, 298 МБ), внутри — проект **Pocket Code (Catrobat)**
«CB In New Colors»: 14 сцен, 102 объекта, 271 скрипт, 122 картинки, 16 звуков.
Предыдущая версия («2.8», релиз `YOU_DON'T_NEED_IT`) остаётся в истории репозитория.

В репозитории лежит:

| что | где | состояние |
|---|---|---|
| скачанный и распакованный оригинал (все текстовые файлы, скрипты, PNG, MP3) | `original/` | 102 МБ, без изменений (два mp3 по 97 МБ не в git — см. `ops/excluded-large-files.txt`) |
| происхождение данных: SHA-256 всех файлов архива, листинг, исключённые крупные файлы | `ops/` | полный аудит |
| картинки и звуки с осмысленными именами + структура проекта для движка | `assets/` | 122 PNG, 16 MP3, `project.lua`, `index.json` |
| конвертер блоков Pocket Code → Lua | `tools/` | покрытие 100% блоков проекта |
| автоматически портированная логика (271 скрипт) | `generated/lua/` | 116 Lua-модулей |
| движок и рантайм | `src/` | C11 + C++17 + Lua 5.4 |
| тесты, сборка, документация | `tests/`, `Makefile`, `CMakeLists.txt`, `docs/` | проходят все проверки |
| Android-проект и сборка APK | `android/`, `.github/workflows/android.yml` | **APK собирается**, [скачать](https://github.com/ehekufa/CB-Classic/releases/tag/apk-latest) |

## Как это устроено

```
архив релиза
   │  (скачивается раннером GitHub Actions: хост release-assets недоступен из песочницы,
   │   см. ops/README.md) 
   ▼
original/  ──tools/catrobat.py──>  разбор формата Catrobat
   │                                 ├── tools/extract_assets.py ──> assets/ + assets/project.lua
   │                                 ├── tools/extract_videos.py ──> assets/videos/ + assets/videos.lua
   │                                 └── tools/catrobat2lua.py  ──> generated/lua/**
   ▼
src/c/     inflate.c, png.c, io.c        — чистый C: чтение/запись PNG без zlib/libpng
src/cpp/   engine, renderer, view_sdl, lua_api, main — C++: сцены, спрайты, ввод, отрисовка
src/lua/   runtime/engine.lua, runtime/scheduler.lua, boot.lua — Lua: семантика блоков
```

* **C** — декодер/энкодер PNG (свой inflate), файловый ввод-вывод, `stb`-подобный слой без
  внешних зависимостей.
* **C++** — сцены и спрайты, отрисовка (поворот, масштаб, альфа, яркость), попадания,
  клоны, мост в Lua, кадровый цикл, оконный бэкенд SDL2 (опционально).
* **Lua** — вся игровая логика: 271 скрипт сконвертированы в читаемый Lua-код, поверх
  него рантайм блоков и планировщик корутин (параллельные скрипты и `wait` — как в Pocket Code).

## Сборка и запуск

Зависимостей нет: Lua 5.4 вендорен в `third_party/lua-5.4`, PNG/inflate — свои.

```sh
make                 # build/cb-classic
make test            # все проверки (сборка, PNG, конвертер, сцены)

# отрисовать 40 кадров меню в out/menu/*.png
./build/cb-classic --frames 40 --scene 1 --out out/menu

# игра: пропускаем регистрацию профилем и играем джойстиком из сценария
./build/cb-classic --frames 120 --scene 26 \
  --profile "61=Гость,62=123,60=3,3=100,4=6,12=1" \
  --script tests/scripts/joystick.txt --out out/igra
```

### Android

Готовый APK лежит в релизе [`apk-latest`](https://github.com/ehekufa/CB-Classic/releases/tag/apk-latest)
и продублирован в ветке как [`dist/cb-classic-debug.apk`](dist/cb-classic-debug.apk)
(`cb-classic-debug.apk`, ~32 МБ, arm64-v8a + armeabi-v7a, minSdk 21). Внутри те же
122 PNG, 16 MP3 и 116 Lua-модулей — с собой ничего носить не нужно. Подробности сборки
и структура `android/` — в [docs/BUILD-ANDROID.md](docs/BUILD-ANDROID.md), отчёт
каждой сборки (sha256, содержимое, лог) — в [ops/apk-report.md](ops/apk-report.md).

### Оконный режим (нужен `libsdl2-dev`):

```sh
make SDL2=1
./build/cb-classic --root . --scene 1     # запускается окно, мышь = палец, Esc = «назад»
# проверить плавность и содержимое кадра без окна и без записи PNG:
./build/cb-classic --scene 26 --bench 120
# снять кадр окна (в том числе на CI с SDL_VIDEODRIVER=dummy):
./build/cb-classic --window --scene 1 --window-frames 30 --screenshot out/shot.png
```

Полезные флаги: `--scene ID`, `--frames N`, `--fps N`, `--size WxH`, `--out DIR`,
`--pixel-scale N` (рендер в N раз крупнее), `--no-sound`, `--set-var "4=0@20"`,
`--script FILE` (сценарий ввода: `press x y`, `type ТЕКСТ`, `key enter|backspace|esc`,
`touch id x y`, `lift id`, `move x y`, `release`, `back`, `scene ID`, префикс `f<N>:` —
применить на кадре N), `--profile "id=значение,..."`, `--check DIR` (синтаксис Lua),
`--check-buttons` (проверить, что каждая кнопка получает нажатие), `--trace ID`
(состояние одного объекта по кадрам: позиция, видимость, яркость, картинка — так
отлаживались перезарядка способностей и прицел), `--verbose` (журнал, состояние
спрайтов и текстовых полей).

Пример: ввод промокода в сцене «Больше» —

```sh
./build/cb-classic --scene 31 --frames 26 --profile "24=100" \
  --script tests/scripts/promo_input.txt --out out/promo --verbose
```

## Сцены

`scenes.txt` новой версии: Загрузка (42), Меню (1), Режимы (70), Игра (26), Онлайн (95),
Магазин ивента (89), Больше (31), Кубы (27), Классы (80), Достижения (96), Яйцо (104),
GoldenEgg (105), Плохая концовка (106), Конец (101). Регистрации и «снежных» сцен
в новой версии нет — стартовый экран сразу загружает прогресс и уходит в меню.
Вся навигация, условия и переходы (`runScene`) перенесены из скриптов.

## Что уже работает

* полный разбор формата Pocket Code: сцены, объекты, картинки, звуки, переменные, массивы,
  «функции» (broadcast-сообщения), вложенные блоки `if/else/repeat/forever`;
* конвертер формул: плоский поток токенов Pocket Code (`["number",3],["number",5],["number",0]`
  → `350`, `["function","random"],["function","("]…` → `E.random(...)`) разбирается в AST
  и печатается как Lua-выражения с корректной семантикой сравнений и склейки строк;
* движок: позиции/поворот/размер/альфа/яркость/слой, смена картинок по id и по имени,
  `goSteps`, попадания по **непрозрачным пикселям** картинки, клоны, текстовые поля, смена сцены;
* **ввод с клавиатуры**: нажатие на поле фокусирует его (в Android открывается экранная
  клавиатура), `Backspace` стирает, `Enter` подтверждает; введённый текст пишется в
  переменную, к которой привязано поле Pocket Code, и в блок `ask`;
* **ввод без Enter не теряется**: нажатие мимо поля считается подтверждением — текст
  уходит в переменную ДО того, как сработают кнопки, поэтому «Ввести», «Выбрать» и слот
  игрока срабатывают с первого раза (раньше кнопка читала старое значение, и нажатие
  приходилось повторять). Модальный вопрос без ответа случайным тапом не закрывается;
* **все поля ввода — белые, как в Pocket Code, с чёрным текстом** (`renderer.cpp` и
  `view_sdl.cpp`): и промокод, и модальный вопрос, и «Имя»/«Пароль» на регистрации.
  Рамка тонкая серая, у активного поля — синяя; подсказка в пустом поле серая.
  Раньше подложка была чёрной, но чёрный цвет «съедал» рамку и подсказку — по просьбе
  вернули белый, как в оригинале;
* **уведомления — как Toast в Android**: тёмно-серая скруглённая плашка (#323232) с
  белым текстом **внизу** по центру (не сверху), несколько сообщений — стопкой вверх;
  проверяется по пикселям кадра (`tests/check_shot.py toast`);
* **нажатия на кнопки**: палец попадает в верхний спрайт, у которого в этой точке
  непрозрачный пиксель; если у него нет скриптов нажатия, нажатие уходит ниже — так
  кнопки работают даже под декоративным слоем. Проверяется командой `--check-buttons`
  на всех 56 кнопках проекта;
* **несколько пальцев одновременно** (джойстик + кнопка атаки): у каждого касания свой
  id и индекс, блоки `touchXByIndex`/`touchIDByIndex` получают своё касание;
* **видео-интро боя**: при входе в битву (сцена 26) проигрывается ролик с тем кубиком,
  который выпал врагом, и только после него включаются джойстик и способности, а враг
  остаётся на месте (без «ноуклипа»). MP4 движок не декодирует — `tools/extract_videos.py`
  заранее режет ролики на кадры PNG (`assets/videos/`, 12 кадров/с, палитровые PNG-8,
  ~1 МБ на все ролики), а `E.video_play(id)` листает их поверх сцены; блоки
  `createVideo`/`deleteVideo` конвертируются в `E.video_play`/`E.video_stop`;
* **касания как в оригинале**: `touchObject` — палец коснулся объекта, `onTouchObject` —
  палец отпущен. Раньше оба срабатывали на нажатие, из-за этого в игре прицел гас
  мгновенно, а удар по врагу считался в момент нажатия, а не отпускания;
* **способности перезаряжаются**: у всех классов одинаковая пауза — **15 секунд**
  (`src/lua/runtime/abilities.lua`): после применения кнопка «Супер атака» гаснет, не
  принимает нажатий и снова становится яркой, когда способность готова; спам во время
  паузы её не продлевает и не перезапускает. В оригинале паузы были разные (0.18 с…
  5.5 с, у рывка Азума вообще нет) и вдобавок «повторять всегда {яркость 85}»
  превращалось в вечный поток, который перебивал возврат яркости — кнопка залипала
  серой. Конвертер теперь сворачивает такой цикл в одну установку яркости;
* планировщик на корутинах: `wait`, `waitIfTrue`, `repeat`, `forever`,
  `repeatIsTrue`, условия `whenTheTruth`, события касания/клона/«назад»;
* **онлайн — настоящий**: игра ходит в Firebase Realtime Database
  (`https://circlebattle1-default-rtdb.firebaseio.com/`) по официальному
  REST-протоколу (`src/cpp/fbnet.cpp`): записи уходят пачкой `PATCH`, чтение —
  опрос узлов раз в 0,35 с, всё в отдельном потоке, поэтому кадр сеть не ждёт
  и игра не фризит. Глобальные ключи (`X1…Y5`, `Rotate*`, `Ивент`, `Написано`,
  скины) сложены в узел `world` — один запрос вместо двадцати, узлы игроков
  читаются как `Имя/Пароль`. На телефоне HTTPS делает Java
  (`android/.../FirebaseNet.java`, вызов через JNI), на десктопе — обычный HTTP
  (для тестов с эмулятором базы). Готовая библиотека `firebase-database` не
  подключена намеренно: она требует Gradle-плагина google-services и файла
  `google-services.json` с ключом проекта, а REST — тот же протокол без ключей;
* **без сети игра тоже работает**: `saves/db.tsv` — локальная копия базы
  (последние значения не теряются, `saveVariable` пишет туда же); сеть
  выключается флагом `--fb-offline`, на десктопе по умолчанию выключена
  (`--fb-url http://127.0.0.1:8899/ --realtime` — прогон с эмулятором базы
  `tests/firebase_mock.py`); адрес базы в игре один — `E.FB_URL` в
  `src/lua/runtime/engine.lua`;
* два бэкенда отрисовки: программный (`renderer.cpp`) пишет PNG-кадры для тестов и
  скриншотов, оконный (`view_sdl.cpp`) выводит ту же сцену SDL-текстурами на GPU;
* **плавность**: кадр на телефоне больше не собирается по пикселям на CPU. Раньше
  сцена «Игра» занимала 70 мс на кадр даже на десктопе (14 fps), теперь картинка идёт
  через `SDL_RenderCopyEx` с вертикальной синхронизацией: 60 fps и ровный шаг времени
  (`--bench N` — замер без записи PNG, `--window` — окно на десктопе);
* **настоящий шрифт — Roboto**: в архиве Pocket Code шрифтов нет, но оригинал
  рисовал системным **Roboto**, поэтому он упакован в APK
  (`third_party/fonts/Roboto-Regular.ttf`, Apache 2.0, кириллица + латиница).
  Если файла нет, берётся системный `/system/fonts/Roboto-Regular.ttf`, дальше
  Noto/Droid с прошивки и в конце DejaVu Sans (`src/cpp/font.cpp`, STB TrueType);
* **звук**: только 16 MP3 самого проекта — декодируются minimp3 и играют через SDL2
  на своих событиях (шаги, выстрел, взрыв, нажатие кнопки: у кнопки играет её
  собственный файл, иначе общее «Нажатие» из проекта). Фоновой музыки нет:
  её не было в оригинале, синтезированную тему убрали;
* **эффекты**: частицы `createRadialParticle`/`setPositionParticle` реально рисуются
  (движок ведёт источники, время жизни, размер, вращение, затухание);
* **изумруды**: валюта новой версии — переменная 93 «Изумруды», её начисляют
  подбор кристалла в игре, магазин яиц и промокоды, а сохраняет и читает сам проект
  (`saveVariable`/`readVariable`). Модуль `src/lua/runtime/emeralds.lua` только
  показывает число, и **только в меню** — полем самой сцены у зелёного изумруда
  (белое, без подписи). На остальных сценах («Больше», «Игра» и прочих) счётчика
  нет вовсе: собственный `hud:изумруды` и поле сцены там гасятся. Переменные 91 и 92
  в новой версии — это ROT2/ROT3 (углы поворота кубов в онлайне), порт их не трогает;
* **промокоды**: на сцене «Больше» рядом с кнопкой «Ввести» есть **поле ввода** —
  белая плашка без подсказки-слова (в оригинале поле создавалось с флагом «off»
  и ввести в него было нечего): тап по полю открывает клавиатуру, Enter подтверждает,
  «Ввести» проверяет код (`MurderOfLove` → +45 кубков, `Eggs`/`GoldenEgg` → сцены
  с яйцами). Текст полей ввода в порте всегда вводимый (`src/lua/runtime/engine.lua`),
  оформление — `style_promo_field` в `boot.lua`;
* **яйцо лопается**: сцена 104 — три тапа, яйцо трескается и разбивается, затем
  случайная награда (`1..5` → +1 яйцо, `6..8` → +2, `9` → «Заяц куб», `10` → «Пасхальник»)
  с toast'ом снизу и возвратом в меню. Раньше эта сцена (как и 101, 105, 106) вообще
  не запускала скриптов: каталог брался как первые два символа слага («10» вместо «104»);
* **кубки**: победа над врагом — это `add_gv(24, 10)` самого проекта, счёт сразу
  сохраняется (`store_var`) и стоит белым в жёлтой полосе панели «Путь к богатству»
  (поле `var:24` сцены «Меню»). Своих модулей у кубков больше нет: в новой версии
  проект ведёт их сам, а старый `trophies.lua` давал бы двойное начисление;
* **значения переменных по умолчанию**: `tools/extract_assets.py` кладёт в
  `assets/project.lua` стартовые значения из `variables.txt` («Кубки» 10009,
  «Яйца» 44, «Скин» 1) — без них игра начиналась с пустых строк;
* **адаптация экрана**: сцена вписывается в экран телефона целиком (letterbox через
  `SDL_RenderSetLogicalSize`), тач-координаты пересчитываются матрицей окна, кадр
  рисуется в разрешении экрана (суперсэмплинг до 2×) — без обрезки и растяжения;
* **диалог «спросить» (`E.ask`) и то, что идёт после ответа**: у кирпича «спросить»
  третий параметр — функция, которую Pocket Code вызывает после ответа (в неё автор
  положил запись ивента и админского сообщения в базу). Порт этот параметр терял,
  поэтому «Введите номер ивента» → «Принять» ничего не записывал и **ивенты не
  запускались**. Теперь ответ не только попадает в переменную, но и вызывает эту
  функцию (`tools/catrobat2lua.py`);
* **диалог «спросить» (`E.ask`)** — настоящий модальный диалог, как в Pocket Code:
  сцена затемняется, сверху крупный белый вопрос (с тенью), под ним поле ввода,
  ниже две кнопки — «Отмена» и «Принять». «Принять» (или Enter) записывает ответ,
  «Отмена» закрывает диалог, ничего не записывая; пока диалог открыт, игра нажатий
  не получает (`Engine::ask_touch`). Всплывающие сообщения — снизу, с подложкой,
  одно и то же сообщение не дублируется;
* **прокрутка списков (камера)**: блоки `focusCameraToObject`/`removeObjectCamera`
  портированы честно — камера смотрит на объект, всё остальное рисуется со сдвигом,
  а помеченные `camera_off` кнопки и стрелки остаются на месте. На этом работает
  листание списка кубов: стрелки вверх/вниз двигают объект «Камера» на ±80 и список
  едет, сами стрелки и «Назад» стоят. «Номер образа» (`imageNumber`) снова как в
  Pocket Code — с единицы, а чужая картинка (`setImageToID` со скином) даёт 0:
  именно так стрелка узнаёт, вверх она или вниз.

## Иконка приложения

Иконка берётся прямо из репозитория — `icon.png` в корне (если файла нет,
используется иконка проекта `assets/icon.png`). Из неё собираются все размеры
для Android:

```
python3 tools/make_icon.py          # пересобрать иконки
python3 tools/make_icon.py --check  # проверить, что все файлы на месте
```

В манифесте теперь `android:icon="@mipmap/ic_launcher"` и
`android:roundIcon="@mipmap/ic_launcher_round"` (раньше стояла стандартная
заглушка Android). Скрипт делает обычные иконки для mdpi…xxxhdpi, круглые
(обрезка по кругу) и адаптивную иконку (`mipmap-anydpi-v26`): картинка лежит
фоном на холсте 108dp, лаунчер сам вырезает круг или квадрат. PIL и ImageMagick
в проекте нет, поэтому PNG читается и пишется на чистом Python (уменьшение —
усреднением, увеличение — билинейно: исходник бывает мелким, например 100x100).

Поменяли `icon.png` — просто запустите скрипт, ничего больше править не нужно.

## Аккаунт и админ

В старой версии игра начиналась с экрана **«Регистрация»** (сцена 77): поля «Имя» и
«Пароль», кнопки «Зарегистрироваться», «Войти», «Подтвердить» и «Не хочу». Новая
версия этот шаг потеряла — сцена просто не попала в список. Порт вернул её: после
заставки игра открывает регистрацию, «Не хочу» ведёт прямо в меню, а набранный вход
не запоминается: экран «Регистрация» каждый раз открывается с пустыми полями
(просьба автора — ник и пароль сбрасываются при каждом перезаходе).

`Имя` и `Пароль` — это переменные 61 и 62, по ним же авторы оригинала проверяли админа.
Админский аккаунт в порте:

```
логин:    admin
пароль:   Kenta2026
```

Пара автора (`1111/1111` и `Dimasi4ek229/5252`) тоже работает. Админ получает кнопку
«Админ панель» на экране «Онлайн»: без такого аккаунта кнопка отвечает тостом
«Нужен аккаунт админа», а «Написать» и «Запустить ивент» остаются скрытыми. Сами
ивенты уходят в базу (`Ивент` = номер) и подхватываются остальными игроками.

Правила базы Firebase в репозиторий не кладутся (просьба автора игры) — они выдаются
текстом в чате вместе с логином админа.

Если вместо панели приходит тост «Нужен аккаунт админа (вход: «…»)», в скобках —
то, что игра прочитала в поле «Имя»: пусто — регистрация пропущена («Не хочу»),
иначе логин набран с опечаткой. Логин сравнивается без пробелов и регистра, пароль —
без пробелов, так что `Admin`/`admin ` тоже подходят.

### Настоящая защита (Firebase Authentication, необязательно)

Пока вход в Firebase не настроен, игра пишет в базу без токена, и правила пускают
запись любого — это защита от мусора, а не от подделки. Чтобы писать в админские
узлы мог только админ:

1. Firebase → **Authentication → Sign-in method → Email/Password → Enable**.
2. **Users → Add user**: `admin@cbclassic.local`, пароль `Kenta2026`.
3. **Project settings → General → Web API key** — вставить в `E.FB_API_KEY`
   (`src/lua/runtime/engine.lua`); для тестов хватает переменной окружения
   `CB_FB_API_KEY`.
4. Поменять правила базы на строгие (выдаются в чате): `Ивент` и
   `Админское сообщение` пишет только `auth.token.email == 'admin@cbclassic.local'`.

Дальше всё само: вошёл админом на «Регистрации» → игра тихо делает
`signInWithPassword` (REST identitytoolkit, `src/cpp/fbnet.cpp`) и каждый запрос
уходит с `?auth=<idToken>`; тост «База: вход админа выполнен» это подтверждает.
Тест на всё это — шаг «сеть: админ входит в Firebase, и строгие правила пускают
запись ивента» (эмулятор базы умеет `--require-auth`).

## Новая версия проекта

Когда автор игры выкладывает новый экспорт Pocket Code (архив в релизе GitHub),
перенос делается одной командой:

```sh
tools/port_new_version.sh super.kortohka.zip        # архив проекта (.zip/.catrobat)
tools/port_new_version.sh super.kortohka.zip --no-build
```

Скрипт распаковывает архив, находит корень экспорта, заменяет `original/`
(файлы больше 50 МБ пропускает и записывает в `ops/excluded-large-files.txt`),
пересобирает `assets/` и `generated/lua`, поднимает `ASSETS_VERSION` в
`MainActivity.java`, собирает движок и прогоняет самотесты.

Перенос заменяет `original/` целиком, поэтому **список сцен нужно проверить**:
«Регистрация» (сцена 77) в новом экспорте автора не значится, но она нужна — порт
добавляет её в `original/scenes.txt` (`["Регистрация",77]` сразу после «Загрузки»).
Если после переноса экран входа пропал, значит строка снова потерялась.

Если архив недоступен локально, тот же перенос умеет делать GitHub Actions:
workflow **port-new-version** (`Actions → port-new-version → Run workflow`),
он качает архив из релиза, коммитит `original/`, `assets/`, `generated/` в ветку,
а обычная сборка после push собирает APK.

## Ограничения (честно)

1. **Начальные координаты объектов в экспорте отсутствуют** — в `objects.txt` есть только
   поворот, размер и путь к картинке. Позиции, которые не задаются скриптом, восстановлены
   по скриншотам сцен и вынесены в `assets/layout.lua`.
2. **Физика** (`addBody`, `isSensor`, `setGravityAllObjects`, `setQuareWHHitbox`) — заглушки:
   записываются в журнал, но не моделируются (движение — `goSteps`, как в скриптах).
3. **Параметры частиц** из блока Pocket Code читаются не полностью: картинка и позиция
   настоящие, а разброс/время жизни/скорость взяты разумными значениями по умолчанию.
4. Звуки — родные MP3 проекта; музыки нет (в оригинале музыкальных файлов не было).
   Онлайн ходит в базу **анонимно** (как и оригинал): правила базы не могут
   отличить одного игрока от другого, пока не включён Firebase Authentication —
   чужой счёт защищён только паролем в пути.
5. **Экранная клавиатура** появляется при фокусе на поле; аппаратную клавиатуру
   и ввод по `Enter` на телефоне делает сама Android, отдельной панели кнопок нет.
6. Один файл в проекте — **JPEG с расширением `.png`**
   (`scene_27/object_47/images/0267_pashalka.png`), он пропускается с записью в журнал.
7. Скрипты-получатели «функций» (broadcast) в выгрузке отсутствуют — вызовы логируются
   как «нет получателей» (особенность модифицированной сборки Pocket Code).
8. Два mp3 по 93 МБ (один и тот же файл) не вошли в репозиторий — см.
   `ops/excluded-large-files.txt` (размер и SHA-256 зафиксированы).

Подробности: `docs/ARCHITECTURE.md` (как устроен порт), `docs/PORTING.md`
(таблица покрытия блоков и все допущения), `docs/PROVENANCE.md` (как данные попали в репозиторий).
