# Аудит импорта

Каталог содержит «бумажный след» того, как данные из релиза попали в репозиторий.

| файл | что внутри |
|---|---|
| `manifest.md` | разбор архива: число записей, гистограмма расширений, крупнейшие файлы, первые пути |
| `zip-listing.txt` | полный `unzip -l` архива |
| `sha256-all.txt` | SHA-256 **всех** файлов архива (в том числе не попавших в репозиторий) |
| `sha256-imported.txt` | SHA-256 файлов, лежащих в `original/` |
| `excluded-large-files.txt` | что не импортировано и почему (размер + SHA-256) |

Импорт выполнял workflow `.github/workflows/asset-probe.yml` (см. `docs/PROVENANCE.md`):
из песочницы хост `release-assets.githubusercontent.com` недоступен, поэтому файл
скачивал раннер GitHub Actions и коммитил результат в ветку.

Проверка: `cd original && sha256sum -c ../ops/sha256-imported.txt`.

Workflow оставлен для воспроизводимости; при следующем пуше в эту ветку он повторит
скачивание и коммит (это идемпотентно).

## apk-report.md

Отчёт сборки Android-версии: пишется CI (`.github/workflows/android.yml`) в том же
прогоне, что собирает APK, и коммитится обратно в ветку. Внутри — размер и sha256
`cb-classic-debug.apk`, число dex-файлов и наличие `MainActivity`, количество
ассетов в APK (PNG, MP3, Lua-модули), данные манифеста и проверка подписи,
плюс хвост лога Gradle. Сам APK в git не попадает: он публикуется в релизе
`apk-latest`.
